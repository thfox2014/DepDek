# DepDek AI-OS x86 MVP

The default graphical desktop is **KDE Plasma 6 on X11**. LightDM signs in the existing unprivileged local OS account and leaves KDE visible; Jiaho is launched manually from the desktop shortcut or application menu, in a normal resizable window. Fcitx5 Simplified Chinese Pinyin is preconfigured for new accounts; Ctrl+Space toggles Chinese and English. Jiaho's standalone recovery session remains available. No private login is bypassed and no new system/application password is introduced. The 800–1100 MB Plasma idle-memory range is a design target, not yet measured on the rebuilt image. See [startup design and verification](../docs/jiaho-os-startup.md).

The stored image, `artifacts/DepDek-AI-OS-amd64.iso`, is the 2026-10-24 build with Jiaho automatic full-screen launch (SHA256: `b8846d73a7505502504e5046f5439605e240df5cfbedef19babe633aa7ed7c27`). The source now defaults to KDE with manual Jiaho launch; that change is not yet in this ISO because the latest rebuild stopped before rootfs creation. Older ISO artifacts were removed during the requested disk cleanup.

2026-10-18 onboarding update: the compact wizard and online/local mode control are included. The current wizard orders network → account → model → working mode. Network setup opens the OS's own settings and does not collect Wi-Fi credentials.

This directory builds a bootable, installable Debian 13 (Trixie) amd64 image. The Jiaho edition shows the approved orange/green brand in GRUB and Plymouth and defaults to the Plasma X11 desktop. Jiaho is a manual launch from the desktop shortcut or KDE application menu, opening as a normal window so the user can adjust display settings first. First boot creates the user's own native account; there is no universal application password. The first successful sign-in grants 1,000 setup credits once. Before chatting, the user selects and saves a model: the bundled assistant, an existing provider, or a custom OpenAI-compatible endpoint. Connection testing is optional and explicit; saving alone never means a provider is connected. The local setup AI costs 10 credits per reply; a user's own provider uses its normal billing, not local setup credits. From the Plasma desktop, **Install DepDek AI-OS** opens Debian's Calamares installer. `jiaho`, `depdek-shell` and a text recovery boot entry remain available.

The bundled default AI is Qwen2.5-0.5B-Instruct Q4_K_M, served by a pinned llama.cpp CPU build on `127.0.0.1:11435` only. The build disables AVX/AVX2/FMA/F16C/BMI2 for older N3160-class boards, pins model revision and SHA256, and downloads nothing at first boot. This is a small local setup assistant, not a cloud credit subsidy or a performance claim for general agents. Custom providers can be configured before the first chat; external test/setup prompts require explicit consent. Account, first-grant, credit reservations and preferences are stored atomically in `.jiaho-onboarding` under application data; reboots drop login state but keep the balance on an installed/persistent filesystem. A nonpersistent Live session loses its accounts/credits on reboot.

The image is built in an amd64 Debian container. On Apple Silicon, the build script uses a native ARM64 QEMU runner for the x86 boot test so the guest does not run nested inside an amd64-emulated builder. Build output is written to `os/artifacts/`:

- `DepDek-AI-OS-amd64.iso` — hybrid BIOS/UEFI installer image.
- `depdek-ai-os-amd64.deb` — the Tauri shell package used by the image.
- `boot-screen.ppm` — QEMU screenshot of the KDE desktop from the matching ISO test.
- `boot-serial.log` — serial output from the matching boot test.
- `iteration-14-boot.log`, `iteration-15-validation.log`, and `iteration-16-validation.log` — earlier boot, regression, and build-log rotation records.

Run `bash os/build-mvp.sh`. It requires Docker Desktop to be running and enough free disk for a Linux builder, Rust/Node dependencies, the live root filesystem, and the ISO. Each run automatically numbers and saves separate build and boot-test logs in `os/artifacts/`. The build script does not remove Docker images or caches; live-build stores its Linux filesystem cache in the named Docker volume `depdek-ai-os-live-build-cache`. Remove that volume, `depdek-ai-os-builder:trixie`, or `os/artifacts/` yourself after saving artifacts if you need the disk space back.

Build staging excludes nested `target`, `node_modules`, and `dist` directories, local environment files, and the host's Node binary. Node is bundled again from the Linux builder. Rust compilation defaults to four jobs. A complete bundled `vosk-model-small-cn-0.22` is reused rather than downloaded again; the final rootfs must still pass the offline recognition test. Missing model files trigger a bounded, retried download.

Rust compiler output is reusable in the separate `depdek-ai-os-cargo-cache` Docker volume. Only the bootstrap filesystem is reused by live-build. The final SquashFS is rebuilt on every run so that an older cached rootfs cannot silently replace the freshly compiled application. Existing rootfs cache files are left untouched but are no longer consumed.

Python voice dependencies are built into a wheelhouse before entering live-build and installed offline in the chroot. A successful build removes its temporary builder container; a failed run leaves the named `depdek-ai-os-build-N` container for diagnosis or resumption, without touching unrelated containers.

Third-party notices are in [`THIRD_PARTY.md`](THIRD_PARTY.md).

Speech recognition uses the Apache-2.0 `vosk-model-small-cn-0.22` model and a Python Vosk runtime installed in the live image. Audio is capped at 30 seconds, stays in memory, and is not saved. The UI requires the user to review the transcript before sending it to an AI provider. Setup offers the bundled local AI without overwriting existing providers. Custom credentials use the existing encrypted application credential flow and are cleared from the input after saving, never embedded in the ISO.

For application-only updates, `bash os/repack-app.sh BASE.iso NEW.deb OUTPUT.iso` runs inside the privileged amd64 builder. Add `--with-startup` to install the fixed reviewed Jiaho session overlay into the staged Debian 13 rootfs as well; dependencies must already be present. It refuses an existing output, installs the supplied package with dpkg, verifies the installed binary against that package, runs rootfs and real offline Vosk assertions, then rebuilds SquashFS and its SHA256 manifest while replaying the base ISO's BIOS/UEFI boot layout. `DEPDEK_SQUASHFS_COMPRESSOR=zstd` selects faster low-level Zstandard after checking kernel support; the default is xz. Extraction/compression use bounded queues, two workers and a 256 MB compression budget. `DEPDEK_ROOTFS_TMPFS=1` optionally puts the unpacked staged tree in a 5 GiB tmpfs (use a >=6 GiB container memory limit); output space checks retain 1 GiB free. Neither mode updates Debian packages or replaces a full OS rebuild when the base system changes. Boot-test the output separately. Earlier model-setup and Wukong artifacts are preserved. Model-setup unit/render tests: `npm run test:ai-os-setup` (Node 24+).

The build checks package architecture, graphical startup, Plymouth assets, model checksum and offline Vosk loading. The QEMU smoke test disables AVX and waits for the KDE desktop, verifies Jiaho is not auto-started, checks the guest display resolution and bundled model health via the live serial console before capturing the screen. Physical hardware/USB, UEFI and a complete target-disk install still require their own acceptance; model health alone does not prove successful inference. Native login/credit tests and real inference results are recorded separately.

The native IPC and data rules are documented in [runtime-welcome.md](../docs/agentos-v2/runtime-welcome.md). Local desktop login is separate from Linux accounts, Webdesk admin and R1 business sessions. The automatic OS display session is not disk encryption or a multi-user security claim.

The former standalone Wukong ISO is no longer retained; the current image uses the unified Jiaho OS shell and setup flow.
