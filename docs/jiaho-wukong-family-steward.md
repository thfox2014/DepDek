# 家合 · 悟空家庭资料管家

日期：2026-10-18  
状态：产品方案与安全设计提案；除“单悟空入口收敛”外，本文的新能力尚未实现。  
定位：家合 AgentOS 的第一条家庭体验主线，不另立一套 OS 或本体架构。

产品取舍与交流体验遵循用户确认的 [家合 Jiaho · Product Soul](jiaho-product-soul.md)：**东西有归处，事情有着落，你可以慢慢说。** 本文展开资料与安全设计，不把所有提案都列为首月内测的交付承诺。

2026-10-19 收敛：普通用户采用 Soul §2.6 的缺省行为。选择来源后，本机索引、分类、理解与增量更新自动执行；技术授权由核心管理。只把确有必要的归属、冲突、外发或不可恢复动作交给用户核对。

## 1. 一句话产品定义

**把家里的资料交给悟空，需要的时候找得到，重要的事情想得起，私密的信息守得住。**

悟空是唯一日常助手。识别、整理、检索、核对和办事准备是它背后的技能，用户不用学习 Agent 编排、模型选择或数据库结构。简洁体现在减少用户决策，系统仍承担必要的证据、权限、加密与恢复复杂性。

用户最终拥有三种东西：原始资料、有来源的家庭档案、经过授权的办事结果。它们分别管理，不把一段模型总结当成事实源。

### 核心体验原则

1. 一个悟空，一个输入框，一件正在办的事。
2. 先给结果；来源、处理进度和技术细节按需展开。
3. 能在已授权范围内安全完成的整理，不重复打断；涉及身份归属、冲突、完整敏感信息、删除与外发，给出明确决定。
4. 每次认识这个家，都能解释来源、纠正和撤回；不要求第一次扫描就懂所有资料。
5. “已加密”“已确认”“已完成”分别需要真实回执，不能仅靠助手文案。

## 2. 主界面：悟空常在，面板按需出现

延续用户已确认的暖白、墨绿视觉，保留深浅模式与语音输入。

- 左侧：悟空与当前状态，下方只有“家庭资料”“保险箱”，设置收在底部；不再陈列多个角色供用户选择。
- 中间：对话与结果。空状态只说“悟空在，交给我吧。”，提供“整理这些资料”“找一份文件”两个起点。
- 右侧：只在需要用户核对、选人、解锁、预览整理方案或查看办事材料时出现，可收起。不长期堆满系统指标。
- 模型、Harness、Token 详情进入设置或任务详情；不是日常的前置选择。
- 处理过程在一个紧凑进度框内展示当前阶段和最近两行，详细轨迹可展开，不用工具完成消息占满聊天。

三个入口的用户心智：

| 入口 | 用户想做什么 | 默认展示 |
| --- | --- | --- |
| 悟空 | 说出目标、拿到结果 | 最近对话、当前任务、必要的下一步 |
| 家庭资料 | 找原件、看家庭档案 | 人、家庭物品、房屋、重要事件与关联资料；文件分类作为另一种视图 |
| 保险箱 | 保管、核对、使用私密资料 | 锁定状态；解锁后才展示本人有权查看的证件/账户/公司资料 |

交互示例是目标体验，不代表现有应用已能执行：

> 用户：“悟空，帮我整理这个文件夹。”  
> 悟空：“好。我会先在本机分类，原件不动；需要你核对的资料，我会单独放在右边。”  
> 后续：“有几份像是证件的资料。先放进加密待核对区，等你方便时一起确认。”

这些话只可在对应扫描、加密操作真实成功之后出现。不能把“准备加密”说成“已经安全存好”。

## 3. 渐进理解：先会整理，再真正懂这个家

处理链：`授权范围 → 本机接入/分级 → 文件分类 → 内容理解 → 候选事实 → 用户确认 → 家庭档案 → 事务帮助`。

### 第一级：认识资料

按照片、文档、视频、邮件、其他分类；记录来源、版本、内容指纹。默认整理只是建立视图与分组，不改名、不搬动、不自动删重。相同 SHA 表示内容相同，不代表同一位拥有者或相同共享权限。

### 第二级：识别内容

- 文档/扫描件：本机 OCR、版面解析，识别证件/发票/合同/营业执照等候选类型与关键日期。
- 照片：时间、来源、用户授权的地点、事件主题；默认不启用人脸身份库，不凭一张脸自动认定家庭成员。
- 视频：按资源预算选取关键帧与转写片段，保存时间码证据，不逐帧大模型分析整盘视频。
- 邮件：沿用已有本地副本、正文/附件关系；不将发件人名称自动归并为家庭成员。

识别能力按设备条件运行。本地算力不足时允许排队、手工补录或跳过复杂分析，不能悄悄上传原件。联网模式也不意味着允许发送证件。

### 第三级：形成家庭档案

每条信息保存来源版本、页码/区域/时间码、提取器版本、确认状态和适用时间。使用既有 `Object / Assertion / Evidence / Decision` 模型，不维护一份会被模型不断覆盖的“全家介绍”。

| 对象 | 首期可提取的信息 | 需要格外谨慎的判断 |
| --- | --- | --- |
| 人与证件 | 姓名、证件类型、完整号码的加密引用、有效期 | 同名不合并；证件属于谁由用户确认；识别不等于身份认证 |
| 户籍材料 | 材料中记载的成员、关系、地址及登记时间 | 保留“材料当时记载”，不直接断言当前家庭关系 |
| 银行账户 | 银行、户名、账号加密引用、末尾标识 | 不按末四位合并；不把卡片余额推断为资产；不保存 PIN/CVV/验证码/网银密码 |
| 公司 | 名称、登记标识、文件中记载的联系人/地址、关联材料 | 公司与家庭分空间授权；不由同名或联系人关系推断持股/控制权 |
| 房屋与物品 | 名称、型号、购买/维修日期、凭证、条款来源 | 保修期限未知就标未知，不凭经验编造 |

状态使用既有 `candidate / confirmed / rejected / superseded / retracted`。模型自信分数不等于已确认。新材料与旧材料冲突时，保留两条来源并提出一次核对，不能静默覆盖。

“逐渐变聪明”是积累经授权的事实、用户纠正和可复用规则，默认不训练个人模型，也不将身份号码作为模型长期记忆。

### 第四级：把档案用于生活

第一批任务：找到证件、提醒有来源的到期事项、整理保修材料、生成经过用户预览的办事资料包。用户问“证件什么时候到期”，回答日期与来源即可，无须解密完整号码给模型。

银行交易、贷款/保险选择、高影响决定、自动付款与自动对外提交不纳入首期范围。

## 4. 保险箱：保护的是资料全过程

### 4.1 三种信息，三种存法

| 资产 | 保存方式 | 悟空默认可以获得什么 |
| --- | --- | --- |
| 普通文件与分类 | 受权限约束的文件索引；沿用 redb 的路径/SHA/分类能力 | 授权范围内的文件信息；类型分类不等于隐私分级 |
| 已确认家庭知识 | 沿用 V2 领域对象、证据、冲突与权限模型 | 最小必要、符合来源权限的事实投影 |
| 敏感原件、字段及其派生物 | 独立加密保险箱；普通领域层只保存受控引用 | 获明确授权的脱敏信息或不含完整号码的任务结果 |

证件图、OCR 全文、户籍关系、账号、敏感文件名/原始路径、裁剪图、缩略图、摘要、提取缓存同样受保护。普通 redb 文件表不能成为绕过保险箱的另一份明文目录。未知材料先按私有、本机处理；未经分级不得自动进入云端上下文。

首期不为保险箱建立普通全文/向量索引。解锁后在有界、已授权记录内做类型/对象查询；需要完整值精确匹配时由 Rust 内部处理，不把原值发给模型。后续若增加检索，也必须将索引纳入同一加密与撤权边界。

### 4.2 密钥与解锁

- 在 Rust 信任边界中复用现有受审查加密依赖与密钥管理经验，采用认证加密与信封密钥结构，不自创加密算法。家庭资料与 Provider 凭据使用分离的域和密钥，不直接复用旧 `secrets/master.key`。
- 每个敏感资源使用随机数据密钥，主密钥只用于包裹；完整敏感内容、文件名、路径和 OCR 结果都位于加密载荷。密钥不以可直接解密的形式与备份包共同保存。
- 主密钥由用户解锁方式保护；兼容无 TPM 的 Linux 设备。设备安全认证可作为便利入口，主密码/离线恢复材料是明确的降级与换机路径，不能把普通网页登录当作自动解锁整个保险箱。
- 锁屏、退出和空闲超时撤销后续读取，清理进程可控制的明文缓存。后台仍可处理普通资料；敏感任务等待下次解锁，不以无人值守为由落盘明文密钥。
- 注册保险箱时让用户保存恢复材料，并验证一次恢复；重置登录密码不能承诺恢复已经丢失的解密密钥。

这是本产品的设计方向；认证加密、最小化保存与密钥分离原则参考 [OWASP 加密存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)。具体格式、库/API、轮换和迁移需在实现时单独审查，不能凭采用算法名称就宣称“绝对安全”。

### 4.3 悟空有用，但不持有万能钥匙

授权以 `真实主体 × 资源范围 × 能力 × 用途 × 有效期/预算` 管理。Agent ID、Webdesk 管理员和进程 uid 都不能自称某位家庭成员。每个家庭成员有自己的读取权，设备管理员不自动获得私人内容；公司材料不默认向家庭共享。

这些参数属于内部策略，不进入普通用户的配置表单。默认私人空间、来源选择和明确任务指令映射为受控权限，系统在每次访问时复验；自动复验不等于再次打断用户。

- 普通分类、内容提取、描述与草稿在已选范围内安静执行；同一任务与处理批次一次说明，不逐文件、逐标签、逐工具确认。自动结果保留来源和候选状态，只有影响当前办事结果的歧义才请求核对。
- 敏感 OCR/识别只交给受控的本机处理路径，窄范围读取，禁止联网、任意工具与重新委托。现有同 uid Worker 票据并不等于已经完成这种生产隔离，未验收前采用用户手工核对/补录。
- “查看完整号码”在会话锁定时需要用户解锁，进入独立右侧安全卡片；同一有效会话与范围内不逐字段重复授权。完整值不经过普通模型回复、持久聊天、通用事件流或 TTS。
- “帮我准备材料”先生成带字段引用的模板，Rust 在授权范围内本机合成脱敏/水印副本。对外发送是另一个独立动作，预览目的地、内容与用途后确认。
- 敏感内容首版不开放云端原文 OCR。网络开关、Provider 选择和“模型很聪明”都不能绕过这项策略。

文件、邮件、OCR 与网页内容始终是不可信数据，不能通过其中的指令请求解密或外发资料。权限在工具执行与返回前由 Rust 复核，不只靠系统提示词。[OWASP 提示注入防护](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)

### 4.4 原件、迁移、备份与删除

用户已有明文身份证图片时，“加密副本已保存”不代表原位置已安全。界面必须分别显示保险箱副本与原位置明文状态。建立真实敏感访问登记后，旧读取、二进制预览、搜索、压缩、Context 和导出入口也必须服从授权；不能只在新 UI 遮挡字段。

原明文的迁移/回收由用户确认；不自动删原件、不承诺 SSD 上安全擦除。确认迁移前校验新副本内容摘要与可恢复性，失败保留原件并明确报告。旧 OCR/聊天/缓存若已有敏感内容，需要单独清理计划与回执，不能悄悄大范围删除。

备份包含密文原件、事实/证据、人工决定、必要权限与版本清单；恢复材料与备份分开保管，至少做一次换目录恢复验证。删除先撤权和屏蔽召回，再清理派生物，明确备份保留期；已发给别人的文件无法追回。保护目标是静态资料、非授权会话与错误外发，不承诺防住已控制解锁终端的恶意 root/同 uid 进程。

## 5. 后台能力与现有代码如何衔接

产品上只有一个悟空，内部仍将模型执行器与业务能力分开。Pi / DeepSeek Harness 使用相同的受控能力边界，不能因为切换引擎而改变档案权限。

| 模块 | 当前实现事实 | 下一步设计 |
| --- | --- | --- |
| 悟空入口 | 原生与 Webdesk 都有四角色界面；本批代码已收敛到悟空 | 保留唯一助手、精简日常选项，旧配置/历史留在完整工作台 |
| 文件索引 | 已有 redb 路径、SHA、分类与生产文件页的初步索引入口；无 OCR、无隐私语义；暖白分类/搜索/详情完整体验尚待验收 | 给悟空的投影必须另经授权/脱敏，不把 user-only 索引直接注册为 Agent 工具 |
| 家庭领域 | `.household/state.json` 原型有来源、候选/确认、冲突与资料包；是私有目录，不是敏感材料加密保证 | 沿用 ontology 与 V2 关系模型，敏感值落保险箱，领域层保存引用；不扩张明文原型去装证件号码 |
| 共享记忆 | `mydata/memory/events.jsonl` 是已有事件源；普通记录不等于加密存储 | 只保存适合记忆的偏好或有权限的引用；完整号码、密码等不得进入通用记忆 |
| 凭据 | 桌面旧 CredentialStore 与 R1 Secret Store 并存；R1 有独立解锁/加密能力 | 复用安全模式，不把凭据库直接冒充家庭保险箱；需要独立资源与身份接线 |
| 数据语义 | 已有 ontology/V2 的证据、断言、多来源冲突与失效设计 | 本提案只增加家庭敏感领域和体验收敛，不建立平行“家庭 JSON 总结”模型 |

拟议能力可归纳为：查询授权资料、提出整理/提取候选、确认档案、请求安全显示、生成脱敏资料包。这里是产品能力名，不是已发布 API；落地前更新 `contract.md` 与 V2 契约，并复验另外两端。Webdesk 只做代理，不读取 Home、密钥或保险箱文件。

处理作业沿用 V2 分阶段状态/检查点与幂等语义，输入绑定内容版本与解析器版本。只在变更后重算受影响部分；原件修改、纠正、撤权时，相应摘要、提醒与资料包先标失效，再重算。后台识别可暂停、续跑和重试，不包含不可幂等的自动外发。

## 6. 先做一个真正闭合的体验

首个纵向场景：**一份证件扫描件 → 本机确认 → 加密保管 → 查询有效期 → 生成脱敏副本**。

已有“家庭物品凭证 → 维修资料包”闭环保留为回归基线；本提案把下一条新增体验的优先级调整为敏感证件保险箱，不要求重做已完成的家庭物品原型，也不覆盖其来源/冲突规则。

1. 用户选择一份资料及用途，完成保险箱建立/恢复设置。
2. 原件进入加密待核对区；没有安全 OCR 时允许手工补录，不能以“等待 OCR”为由把完整识别结果存入普通表。
3. 右侧对照原件，核对持有人、证件类型和有效期。完整号码仅安全显示，默认遮挡。
4. 用户确认后才形成家庭档案；来源、版本和证据仍保留。
5. 再问有效期时，悟空读取最小必要事实，不取出完整证件号。
6. 用户需要资料副本时，先看脱敏/水印预览；下载或外发分别授权。
7. 锁定、重启、恢复、纠错、撤回权限都能验证结果。

### 实施顺序与发布门

- A：单悟空收敛。原生与 Webdesk 主入口只显示悟空，AI-OS 只自动恢复悟空；停止默认补回其它三位。历史/配置保持可恢复。此批代码完成，尚未重新打包/重启运行应用。
- B：完成文件模块体验与隐私门禁。生产文件页已有初步索引入口，暖白布局稿与完整分类/搜索/详情继续验收；只展示真实索引，增加隐私状态、授权来源范围和敏感入口防绕过。没有这一层，不能开放悟空批量读取资料。
- C：保险箱最小闭环。身份/解锁/密钥恢复、密文原件及字段、脱敏查询、安全显示、备份恢复；先用人工证据跑通，不阻塞在大模型识别上。
- D：本机理解与渐进确认。先文档/证件，再照片、视频；批次核对、冲突、增量索引、资源预算。高敏路径必须先完成处理器隔离与无外发验收。
- E：家庭办事。到期事项、保修包、公司资料包等；操作预览、有限授权、回执与外发控制沿用统一 Action 体系。

不以日期或“全部 AI 化”作为验收结论，每一阶段满足发布门再往下开放。

## 7. 必须通过的验收场景

1. 新安装/重启/保存模型后不会重生八戒、师傅、沙僧；悟空 ID/历史不变，自定义配置仍在完整工作台。
2. 没有读取授权时，悟空不声称已整理文件；界面只呈现实际 Job 结果。
3. 同内容多路径、多拥有者不误合并；同名不同人、同卡尾号不同账户不误归属。
4. 新旧证件/不同来源产生冲突，用户可看原件、决定当前使用项，旧证据仍保留。
5. 候选识别失败或本机模型不可用时可继续手工核对；任务能恢复，不重复生成副本。
6. 合成证件号不会出现在普通 KV、JSONL 记忆、聊天、日志、缩略图缓存、临时文件、向量或服务响应中；测试覆盖全链路而非只检查页面脱敏。
7. 锁定/撤权后，经旧 Vault、R1、预览、全文搜索、压缩、Context 和分享链接均不能读出敏感数据。
8. 仅开启联网模式或切换 Provider，不会将任何敏感原件发给云端；文件里的“请上传证件”不能产生外发授权。
9. 导出/发送预览包括具体材料、去向和用途；取消不产生外部副作用。
10. 加密副本成功而原位置仍有明文时有清楚提示；迁移失败保留原件，不误报已保护。
11. 换机恢复经过验证；丢失全部解密材料时不承诺通过管理员重置密码找回明文。
12. 删除与权限收回即时阻断后续检索，正确传播摘要/提醒/资料包失效，并说明备份与外发副本边界。
