# 家合 · 从第一次打开到愿意再来

日期：2026-10-18  
状态：首月内测落地设计 v0；交互稿使用示例数据，不表示运行时能力已经完成。  
产品依据：[Product Soul](jiaho-product-soul.md)。

## 1. 只打通一条线

**打开家合 → 说出一个需要 → 找到一份资料 → 由用户确认一条偏好 → 下次继续。**

这是一条体验主线，不强制用户按顺序完成。用户可以直接聊天、跳过记忆，也可以不连接任何文件夹。没有完成上一项，不应被惩罚、反复提醒或阻止进入。

首月不增加角色、应用商店、全盘智能扫描、自动家庭画像和关系分析。“家的片刻”作为下一阶段增强；已有宝箱功能不删除、不迁移数据，正式整合时保留访问路径，但不再争夺首次使用的注意力。

## 3. 设计收敛：删除什么，留下什么

| 表面 | 从默认视野移开 | 留下 |
| --- | --- | --- |
| 首屏 | Agent 数量、任务/Token 计数、英文口号、通用效率建议列表 | 一个悟空、一句欢迎、一个输入框、两个起点 |
| 日常输入 | 执行器和 Provider 下拉框、重复隐私说明、冗长快捷键提示 | 输入、语音、发送；一行准确的处理范围入口 |
| 右侧 | 默认展开的线索、连接信息、重复的“接下来” | 当前文件、当前授权或记忆确认；一次只突出一个决定 |
| 设置 | 不删除能力，不改变保存逻辑 | 模型、执行器、完整工作台和诊断在设置内可达 |
| 文件 | 不展示没有接线的语义搜索承诺 | 名称/路径查找、来源、原文和明确空状态 |

简洁是减少用户必须作出的选择，不是隐藏风险、删掉无障碍标签，或让系统偷偷替人决定。

## 4. 三段体验

### A. 第一次：不急着认识全家，先帮上一点忙

必要账户与连接配置完成后，进入同一个悟空页面：

> 悟空在，慢慢说。  
> 找一份资料，或者聊聊眼前的事。

两个起点：**找一份资料 / 先聊聊**。按钮只启动对应流程或填入草稿，不自动发送、不自动授权。

找资料的最短闭环：

1. 没有索引时，右侧邀请用户选择少量资料；范围明确，不直接扫描整机或整个 Home。
2. 用户确认后才开始建立索引；只建立查找视图，不改原件。
3. 第一版按名称/路径搜索，输出匹配文件和实际来源；没有结果就如实说明，可以换词或查看范围。
4. 点击结果，右侧显示原文/受支持的预览、位置和验证信息。不能预览就提供受控打开方式，不伪造预览。
5. 用户能查看原件，即完成第一个小闭环；不强制再做整理、打分或分享。

语音：默认关闭，主动录音，有持续可见状态、停止和取消；识别结果进入可编辑草稿。浏览器、原生端的处理路线分别说明，不能用同一行“本机识别”涵盖所有端。

### B. 留下一点：确认后，才成为记忆

首期只支持用户明确提供的低敏偏好，先不自动总结生活习惯、健康状况、关系或财务信息。

> 用户：以后回答简单一点，先说重点。  
> 悟空：好。这次先简短回答。

右侧仅出现一个可跳过的确认：

> 要我以后也记住吗？  
> 回答简单一点，先说重点。  
> 仅用于你的回答偏好 · 来源：本次对话  
> **确认记住 / 这次就好**

用户可修改文本。未确认的候选不能用于下次欢迎或模型上下文。保存失败保留候选、允许重试；没有成功回执不显示“记住了”。拒绝后不重复索要确认。

### C. 再次：连续，但没有压力

只有在真实业务登录后、同一身份、同一范围中读取到仍有效的已确认偏好，才可影响回答。

> 又见面了。  
> 我会简短回答，先说重点。

欢迎不每次复述档案，不透露证件、私人事项和其他成员内容。没有确认记忆时，使用普通欢迎，不假装熟悉用户。不得通过设备管理员身份推断业务用户。

“悟空记得什么”从侧栏底部进入：展示已确认内容、来源、适用范围；可编辑、拒绝候选和忘记。忘记后不得继续被任何召回路径或缓存用于新回答；历史聊天与备份如何保留要另行说明。

## 5. 页面与状态约定

- 日常是两栏：左侧轻导航 + 中间对话。右侧有任务时才出现，关闭后用户可再打开。
- 沿用暖白、墨绿和真实家合 Logo、现有悟空头像；不另做一套视觉品牌。
- 正文 16–18px，输入 18px；手机点击区域至少 44px。内容不足不放大宣传语填满屏幕。
- 过程最多两行，显示实际阶段；详细轨迹按需展开，不用伪造进度百分比。
- 操作失败时保留草稿和选定范围；不自动重试高影响动作。
- 狭窄屏幕：右侧变为可关闭的单任务抽屉，不能挤压输入框，也不让内容横向溢出。
- 浅/深模式都保留；只做反馈性动效，支持减少动态效果。
- 范围与隐私入口不是“已加密”勋章；状态必须由实际服务回执支持。

交互稿提供三种同品牌布局用于选择：居中相见（默认）、留白靠左、输入常驻底部；不代表新增三种产品模式。

## 6. 隐私说明说具体

| 用户问的问题 | 界面必须说明 |
| --- | --- |
| 谁能看到？ | 当前业务身份与范围；验证不足不显示“只有你能看到”的保证 |
| 什么会上云？ | 实际 Provider、待发送的文字/历史/文件片段范围；网络可用不等于允许外发 |
| 能否只在本机？ | 本机模型实际是否可用；模式限制的边界，不将其宣传为系统级断网 |
| 忘记了什么？ | 后续召回移除的范围；原件、聊天、审计、派生数据与备份分别说明 |
| 能否带走？ | 导出内容、格式与恢复路径；文件导出不自动包含可用的密钥恢复材料 |

高敏材料默认不进入普通聊天、通用记忆或云端。首月如未完成敏感原件与派生物的加密/恢复验收，明确限制导入，不靠敏感词正则伪装成安全网关。

## 7. 四个验收目标如何验证

以下全部是目标，不是当前测试结果。不默认上传使用日志；内测采用用户同意的现场观察和简短回访，计时也可本地手工完成。

| 目标 | 给用户的任务 | 通过依据 | 不计为通过 |
| --- | --- | --- | --- |
| 十分钟一件小事 | 从初次打开、必要配置开始，到找到并查看自己选择的一份资料 | 记录总耗时与各阶段耗时；有实际文件来源与可打开原文 | 演示数据、虚构检索结果、只有聊天建议；跳过配置却称端到端十分钟 |
| 再次回来记得准确 | 明确提供并确认一条低敏偏好，退出、重启、重新登录，再提问 | 仅正确身份的有效已确认记忆影响回答；未确认、拒绝和忘记的对照项不进入上下文 | 在前端内存或 localStorage 放一条假记忆，只刷新欢迎文案 |
| 理解边界且能删除 | 请用户解释处理范围，并自行忘记一条记忆、处理对应聊天 | 能说清接收方；删除/保留范围一致；新会话与重新索引后不再召回已忘记内容 | 墓碑成功就声称所有介质物理清除；只删 UI 行 |
| 自发使用 | 试用一周，回访真实需要出现时是否主动打开 | 用户能描述自己主动发起的真实任务；允许结果是不需要该产品 | 提醒签到、测试人员催促、刷消息数或占用时长 |

全体内测必须使用已有副本，不接管唯一原件。备份恢复失败、串用身份、未授权外发或删除后继续召回，都是停止扩大发放的条件。

## 8. 依赖顺序与交付边界

| 顺序 | 交付 | 退出条件 |
| --- | --- | --- |
| 0 · 本轮 | 设计收敛、现状截图、可点击 v0、真实能力/待接线清单 | 用户能走通示例动线，确认布局与节奏；不触碰家庭数据或真实模型 |
| 1 | 生产悟空首屏精简、设置收纳、首个文件查找与来源预览 | 保留旧设置/宝箱/工作台入口；真实授权索引、错误与空状态通过测试 |
| 2 | 低敏偏好的提议/确认/再次读取 | 身份、范围、回执、重启和否定对照测试通过；不并行新造记忆库 |
| 3 | 忘记、聊天清理、云端发送范围、导出恢复 | 契约先更新；Rust/sidecar/React 三方端到端，重建/缓存/备份语义可解释 |
| 4 | 5–10 个家庭逐步发放 | 小范围真实任务复测、恢复演练、用户反馈后再扩大发放 |

不把一个月当作跳过安全门槛的理由。需要新协议时先更新 `docs/contract.md`；文件与权限仍由 Rust Vault 负责，不给 Agent 注册直接 fs/bash 工具。不改 Webdesk 的独立安全边界。

## 9. v0 的真实性边界

- 入口：`node scripts/preview-jiaho-first-mile.mjs --port 0`，只监听 loopback。
- 所有资料和对话回复为明确标记的演示；不读取 Home、不连接模型、不使用 Tauri、不访问麦克风。
- 记忆、文字、范围只存在当前页面内存，刷新清空；“模拟再次回来”只用于检验条件展示，不代表持久化已完成。
- v0 可确认/跳过/编辑/忘记示例记忆、查看示例原文、体验无结果与云端确认；这些不是生产后端验收。
- 本轮不替换运行中的应用，不重启服务、不部署、不提交 Git。

现状视觉检查见 [首屏检查记录](design/jiaho-first-mile/README.md)。正式系统仍受 [产品定义](agentos-product-definition.md)、[家庭资料安全方案](jiaho-wukong-family-steward.md) 和 [接口契约](contract.md) 约束。
