# DepDek V0.2 PRD：本地优先收件箱与邮箱连接基础版

> 版本：V0.2 / Sprint 1
>
> 状态：已实现（以本文、`V0.2 Design.md` 和 `V0.2 Testcase.md` 为交付基线）
>
> 上游：V0.1 产品壳、`docs/depdek-prd.md`、`docs/depdek-refactor-roadmap.md`
>
> 核心承诺：我的邮件回到我的 Home；AI 只整理，不代替我发送。

## 1. 版本概述

V0.1 已经提供 DepDek 的个人工作台壳，但“我的邮箱”仍属于 Deep Work 的兼容入口。本 Sprint 把邮件提升为独立的一级领域 **收件箱（Inbox）**，打通一条可验证的本地优先闭环：

> 配置一个邮箱 → 手动收取 → 邮件落到本地 Home → 像普通邮件软件一样阅读和处理 → 通过本地规则/模型给出整理建议。

V0.2 继续复用 V0.1 的 Vault、审计、sidecar IMAP bridge 和 contract v1，不引入云端模型，不执行远端写操作，不把邮件正文或邮箱凭据上传给第三方。

## 2. 用户与问题

### 2.1 目标用户

重度使用一到多个邮箱、希望自己掌握数据副本，同时需要快速识别待办和风险的个人用户。

### 2.2 当前痛点

- 邮件藏在 Deep Work 入口，不像正常邮箱一样可浏览和处理；
- 邮件、任务和本地工作台之间没有清晰的数据边界；
- 用户不知道一次收取是否成功、数据落在哪里、AI 是否会外发；
- 多邮箱切换和本地缓存状态不稳定，刷新后容易丢失处理痕迹。

## 3. 目标与非目标

### 3.1 本 Sprint 目标

| 编号 | 目标 |
|---|---|
| G-01 | 收件箱成为独立一级入口，Deep Work 不再重复展示“我的邮件”树 |
| G-02 | 支持新增/编辑 IMAP 账户，账户配置通过 Vault 保存并可重新读取 |
| G-03 | 支持手动增量收取，邮件以 Markdown 原始副本落在本地 Home，UID 不重复 |
| G-04 | 支持账户切换、列表、阅读、已读、星标、归档和本地状态持久化 |
| G-05 | 提供清晰可见的“AI 整理”入口，只对本地已同步邮件生成只读建议 |
| G-06 | 断网、认证失败、空账户、空邮件等状态均可解释、可恢复 |

### 3.2 明确不做

- OAuth、OS Keychain/Secret Store、凭据轮换；
- 自动后台同步、Push、复杂 IMAP 文件夹同步；
- 邮件发送、回复、转发、远端删除、日历写回等外部写操作；
- 云端大模型、云端摘要、未经预览的网络调用；
- SQLite Canonical `Message`、全文搜索、附件内容预览；
- 多用户协作和多设备同步。

这些能力进入 V0.3～V0.9 的路线，不因 UI 出现入口而提前承诺。

## 4. 核心用户旅程

### Journey A：首次连接与收取

1. 用户进入「收件箱」；
2. 无账户时看到空态和“添加账户”；
3. 填写显示名称、邮箱地址、IMAP 主机、端口、授权码/密码、邮箱文件夹、TLS；
4. 点击“保存账户”，配置写入当前 Home 的 `mail/accounts.json`；
5. 点击“收取邮件”，显示同步中、成功/无新邮件或按账户显示失败原因；
6. 成功消息写入 `mail/<account>/`，刷新列表并保留 `last_uid`。

### Journey B：像邮箱一样处理

1. 用户在左栏切换收件箱、已标记、草稿、已归档或账户；
2. 列表展示未读点、发件人、主题、摘要、时间、星标；
3. 点击邮件打开阅读面板，并将其标记为本地已读；
4. 用户可以星标或归档，状态写入可重建的 `mail/index.json`；
5. 刷新或重新打开后，邮件正文和本地处理状态仍可恢复。

### Journey C：本地 AI 整理

1. 用户点击“AI 整理”；
2. 面板明确说明“仅使用本地 Home 中的邮件副本，不上传”；
3. 系统按规则/本地能力给出优先处理、付款截止、待回复等建议；
4. 每条建议显示来源邮件，用户点击后回到邮件阅读；
5. AI 不自动归档、不发送、不创建外部任务。

## 5. 功能需求

### 5.1 收件箱与账户

| ID | 需求 | 优先级 | 验收口径 |
|---|---|---|---|
| INBOX-001 | 收件箱为一级领域入口 | P0 | 导航可进入，Deep Work 无“我的邮件”树 |
| INBOX-002 | 账户选择器 | P0 | 显示账户名称和邮箱，可在账户间切换；无账户有 CTA |
| INBOX-003 | 新增/编辑账户 | P0 | 必填校验、端口范围、TLS 默认开启，保存后可读回 |
| INBOX-004 | 邮件列表 | P0 | 显示未读、发件人、主题、摘要、日期和星标；最多加载当前目录最近 100 封 |
| INBOX-005 | 阅读面板 | P0 | 显示 From/To/Date/Subject/body，长正文可滚动，特殊字符不破坏布局 |
| INBOX-006 | 本地文件夹 | P0 | 收件箱、已标记、草稿、已归档可切换；V0.2 的状态不写回远端 |
| INBOX-007 | 本地状态 | P0 | 已读、星标、归档写入 `mail/index.json`；索引丢失时可回退为默认状态 |
| INBOX-008 | 手动收取 | P0 | 调用 `mail_fetch`，展示同步中、成功、无新邮件、认证失败和网络失败 |

### 5.2 AI 整理

| ID | 需求 | 优先级 | 验收口径 |
|---|---|---|---|
| AI-001 | 本地 AI 整理入口 | P0 | 按钮显眼，面板说明数据范围和执行位置 |
| AI-002 | 建议来源可追溯 | P0 | 每条建议来自本地邮件 subject/body 摘要，并可点击回原邮件 |
| AI-003 | 建议只读 | P0 | 不修改邮件、文件夹、第三方状态，不产生发送/写回调用 |
| AI-004 | 空态与失败 | P1 | 无未读邮件显示空态；整理失败不影响阅读 |

### 5.3 隐私与可靠性

| ID | 需求 | 优先级 | 验收口径 |
|---|---|---|---|
| SEC-001 | 邮箱凭据不进入 AI 上下文 | P0 | password 只存在表单和兼容配置路径，不出现在建议、日志和邮件列表 |
| SEC-002 | 本地数据边界可见 | P0 | UI 明示“邮件回到本地 Home”“本地预览不连接外部服务器” |
| SYNC-001 | 增量与幂等 | P0 | 仅处理 `uid > last_uid`，重复收取不产生重复 Markdown |
| SYNC-002 | 单账户隔离 | P0 | 单账户失败不阻断其它账户，错误挂在对应结果项 |
| UX-001 | 双运行态 | P0 | 浏览器预览使用 fixture 且无网络；Tauri 使用 Vault/sidecar |

## 6. 数据边界与已知债务

V0.2 继续使用 contract §7 的兼容布局：

```text
<vault-root>/
├── mail/accounts.json       # 账户与 IMAP 增量游标
├── mail/<account>/*.md      # 邮件原始本地副本，来源事实
└── mail/index.json          # 可重建的已读/星标/归档 UI 状态
```

`mail/index.json` 不保存密码，不是长期 Canonical 主库；V0.3 会将邮件导入 SQLite `Message`，并保留 `SourceRef` 回到 Markdown。现有 `accounts.json` 的密码明文是 V0.2 接受的兼容债务：UI 不展示明文、AI 不读取凭据、审计不记录凭据；V0.4 必须以 OS Keychain/Secret Store 和 `CredentialRef` 替换它。

## 7. 成功指标与发布门槛

### 7.1 目标指标

- 首次账户配置：正常网络下不超过 3 分钟；
- 本地缓存收件箱首屏：不超过 2 秒；
- 本地整理建议：不超过 1 秒或给出明确处理中状态；
- 连续两次收取不产生重复消息；
- P0 用例通过率 100%，浏览器页面错误日志为 0；
- 未经用户明确操作的外部写调用：0 次，云端调用：0 次。

### 7.2 发布门槛

- `npm run build` 通过；
- `npm --prefix sidecar run build && npm --prefix sidecar test` 通过；
- `cd src-tauri && cargo test --no-default-features` 通过；
- 浏览器回归覆盖账户、收取、阅读、已读、星标、归档、AI 本地声明和 Deep Work；
- Tauri `.app` 签名校验、DMG 校验通过；未配置 Apple notarization 时必须在发布说明中标注。

## 8. 已知限制与下一 Sprint 入口

- V0.2 不提供账户删除；下一版本需要定义“只删连接/保留本地副本”的确认流；
- V0.2 仍使用明文兼容配置，V0.4 Secret Store 为安全硬门槛；
- 草稿、附件和复杂 IMAP 文件夹暂为 UI 占位；
- `mail/index.json` 损坏时按原始 Markdown 重建，不能阻塞收件箱打开；
- 下一版本优先做 Home manifest、SQLite Canonical Message 和迁移回滚。
