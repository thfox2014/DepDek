# DepDek PRD：Local-first 个人数据工作台

> 版本：v0.1
> 阶段：重构立项稿
> 关联概念设计：[depdek-concept-design.md](./depdek-concept-design.md)

## 1. 背景

现有 Agent Workbench 已具备安全文件 Vault、审计日志、Node Agent sidecar、模型 Provider 配置、邮件拉取和多会话前端，验证了“模型只能通过 Rust 受控能力访问本地数据”的技术方向。

但现有产品以数据文件夹和 Agent 会话为中心，用户需要主动进入对话、理解文件结构、配置模型并组织 Agent。它尚不能解决个人数据分散、凭据失控、来源不统一、长期记忆不可治理，以及本地/云端模型职责不清的问题。

本次重构将产品中心从“Agent 工作台”改为“个人数据中心与行动工作台”，保留并扩展现有 Rust 信任边界。

## 2. 目标

### 2.1 产品目标

1. 用户可以建立一个由自己持有、可迁移、可离线使用的 Personal Data Home。
2. 用户可以安全连接关键服务，将数据增量同步到本地并保留来源。
3. 用户可以跨来源检索、整理和关联个人数据。
4. 本地模型可以执行日常理解、提取和组织任务，并形成可审查的长期记忆。
5. 复杂策略任务可以在最小披露和显式策略下升级到云端模型。
6. 外部服务调用统一经本地 Credential Broker 与 Policy Engine，形成审批和审计闭环。
7. 用户在“今天”工作台能看到当前状态、承诺和下一步，不必先进入聊天。

### 2.2 MVP 成功标准

- 新用户在 10 分钟内完成 Home 创建、一个连接和首次同步。
- 90% 的已同步记录可通过统一搜索在 2 秒内返回首屏结果（本地中等规模数据集基准另行定义）。
- 所有外部写操作和云端模型调用均产生可查看回执。
- 凭据明文不进入 Personal Data Home、日志、模型提示词或前端持久状态。
- 断网时可浏览、搜索、编辑本地记录，并能将联网操作安全排队。
- 用户能查看、修改、删除全部长期记忆项及其来源。

## 3. 目标用户

### 3.1 核心用户

重度使用多个数字服务、重视隐私与长期知识积累的个人专业用户，包括独立开发者、研究者、创作者、自由职业者和小团队负责人。

### 3.2 Jobs to Be Done

- 当我的信息散落在不同服务时，我想在一个本地入口找到完整上下文。
- 当消息和会议产生承诺时，我想自动发现但由我确认，不遗漏下一步。
- 当我规划复杂目标时，我想让 AI 理解我的真实约束，同时避免把全部私人数据交给云端。
- 当 AI 代表我行动时，我想知道它读了什么、将发送什么、做了什么，以及如何撤销。
- 当我更换服务或模型时，我想保留自己的数据、记忆和工作方式。

## 4. 产品范围

### 4.1 P0：MVP

- Personal Data Home 创建、迁移、状态检查。
- OS Keychain 凭据存储和 Credential Broker。
- 连接中心与连接器 SDK。
- 邮件、日历、本地文件三个首发连接器。
- 增量同步、重试、冲突记录、来源追踪。
- Canonical Data Store（SQLite + FTS + 对象存储）。
- “今天”、待办、收件箱、知识、文件、连接、数据与隐私七个主模块。
- 全局搜索/指令栏。
- 本地模型运行状态、模型选择与本地推理。
- 云端 Model Gateway、数据预览和逐次审批。
- 统一 Action/Approval/Receipt 模型。
- 长期记忆的候选、确认、修改、删除。
- 数据访问、同步、模型外发和外部写操作审计。

### 4.2 P1

- 双向任务连接器、笔记连接器、联系人统一。
- 项目与关系视图。
- 自动化规则和低风险自动执行。
- 加密备份与多设备只读恢复。
- 可插拔向量索引与多模态本地解析。
- Domain Pack：学习、健康、财务等。

### 4.3 不在当前范围

- 云端同步主库与多人协同。
- 插件市场和不受控第三方代码执行。
- 自动进行付款、交易、医疗或法律决策。
- 移动端完整客户端。
- 默认提供任意 shell 或网络访问。

## 5. 信息架构

### 5.1 全局框架

- **左侧导航**：稳定领域与系统入口。
- **顶部栏**：时间/问候、全局搜索与指令、快速创建、同步和模型状态。
- **主工作台**：响应式卡片网格，卡片可固定、隐藏、拖拽、调尺寸和展开。
- **Copilot Drawer**：围绕当前页面提供解释、草拟和规划。
- **Action Sheet**：所有中高风险行动的计划、数据范围、审批和执行结果。

### 5.2 首发导航

今天、日历、待办、收件箱、知识、文件、自动化、连接、记忆、数据与隐私、设置。

### 5.3 “今天”工作台

- 日期、时间、问候与本地状态。
- 今日时间轴。
- 今天要完成的任务。
- 需要处理的收件/审批/同步冲突。
- 近期项目或主题脉搏。
- 连接器、本地模型、存储和备份健康度。
- DepDek 建议：每条建议必须显示依据，并支持忽略和反馈。

## 6. 核心数据模型

### 6.1 统一基础字段

所有 Canonical Record 至少包含：

```ts
type CanonicalRecord = {
  id: string;
  type: string;
  title?: string;
  body?: string;
  created_at?: string;
  updated_at?: string;
  source_ref: SourceRef;
  provenance: Provenance[];
  sensitivity: "public" | "personal" | "sensitive" | "restricted";
  local_state: "clean" | "dirty" | "conflict" | "deleted";
  schema_version: number;
};
```

`SourceRef` 能定位到连接、远端账号、远端对象 ID 和原始快照。Derived Record 必须记录生成模型/规则、输入记录和版本。

### 6.2 关键系统实体

- `Home`：本地数据家园配置和 schema 版本。
- `Connection`：外部服务授权与同步配置。
- `CredentialRef`：指向 Secret Store 的不透明引用。
- `SyncCursor`：按连接和数据类型保存增量位置。
- `Entity`：Person、Organization、Project 等主实体。
- `Record`：Message、Event、Task、Document 等内容记录。
- `Relation`：实体/记录之间的有向关系。
- `MemoryFact`：可治理的长期记忆。
- `Policy`：数据、模型、连接和行动策略。
- `Action`：待执行或已执行的结构化操作。
- `Approval`：用户授权范围与时效。
- `Receipt`：同步、模型外发和外部执行回执。

## 7. 功能需求

### 7.1 Home 与存储

- **HOME-001** 用户可在本地创建或选择 DepDek Home。
- **HOME-002** 系统启动时检查目录权限、空间、schema 和索引健康度。
- **HOME-003** 用户可导出归一记录、原始对象、策略和审计清单；凭据默认不导出。
- **HOME-004** 索引均可从主记录重建，不能成为唯一数据源。
- **HOME-005** Home 迁移必须使用事务式清单，失败后原 Home 仍可用。
- **HOME-006** 用户可选择全盘加密依赖或应用层敏感对象加密。

### 7.2 凭据与连接

- **CONN-001** 凭据保存到 OS Keychain/Secret Store，数据库只保存引用。
- **CONN-002** 连接器通过 Credential Broker 使用凭据，不能读取可展示明文。
- **CONN-003** 新建连接前展示权限、同步方向、数据范围和风险。
- **CONN-004** 支持 OAuth、API Token、App Password 等受控授权方式。
- **CONN-005** 用户可暂停、重新授权、撤销和删除连接。
- **CONN-006** 删除连接时分别选择“保留本地副本”或“删除本地数据”。
- **CONN-007** 连接健康页显示最近同步、失败原因、权限和下次计划。
- **CONN-008** 每个连接器声明固定网络目的地与 capability，禁止任意网络。

### 7.3 同步与归一化

- **SYNC-001** 支持首次全量/范围同步和后续增量同步。
- **SYNC-002** 同步任务可暂停、恢复、重试，并使用幂等键避免重复。
- **SYNC-003** 保存远端原始快照或等价 provenance，归一化不覆盖来源事实。
- **SYNC-004** 远端与本地并发修改形成冲突记录，不静默覆盖。
- **SYNC-005** 同步状态进入全局健康中心和相关模块空态。
- **SYNC-006** 离线时联网任务进入持久队列，恢复联网后按策略执行。
- **SYNC-007** 用户可按连接、时间和数据类型重新同步或删除缓存。

### 7.4 搜索与知识

- **SRCH-001** 全局搜索覆盖标题、正文、参与者、标签、时间和来源。
- **SRCH-002** 搜索结果按类型、来源、时间和敏感级别筛选。
- **SRCH-003** 语义检索可关闭；关闭后全文和结构化搜索仍完整可用。
- **SRCH-004** 每个摘要、答案和关系均可打开原始来源。
- **SRCH-005** 搜索/问答明确区分事实命中、模型推断和行动建议。
- **SRCH-006** 未授权的受限记录不能进入模型上下文。

### 7.5 任务、收件箱与日历

- **WORK-001** Message/Event/Document 中抽取的任务先进入待确认收件箱。
- **WORK-002** 用户可确认、修改、合并、忽略和追溯任务来源。
- **WORK-003** Task 可关联 Project、Person、Event 和 Source Record。
- **WORK-004** “今天”聚合到期、排期、建议和等待项，不改变远端状态。
- **WORK-005** 写回第三方任务或日历必须生成 Action；默认逐次确认。
- **WORK-006** 时间冲突和延期建议必须展示依据，不自动改日程。

### 7.6 本地模型

- **LMAI-001** 用户可配置和检测本地 OpenAI-compatible Runtime。
- **LMAI-002** 系统显示模型状态、能力、上下文上限和预计性能。
- **LMAI-003** 本地模型默认处理分类、抽取、摘要、检索增强和脱敏。
- **LMAI-004** 模型无权直接访问文件、凭据和网络，只能使用受控工具。
- **LMAI-005** 模型输出的 Derived Record 记录模型、版本、输入与时间。
- **LMAI-006** 模型切换后允许重建派生索引，不影响主数据。

### 7.7 云端模型网关

- **CLAI-001** 所有云端模型请求必须经过 Model Gateway。
- **CLAI-002** 网关生成外发预览：目的、模型、字段/记录范围、脱敏项、预计成本。
- **CLAI-003** 策略支持仅本地、逐次询问、指定任务自动三档。
- **CLAI-004** restricted 数据默认禁止外发，除非用户对本次任务显式覆盖。
- **CLAI-005** 云端响应落本地时记录 Provider、Model、请求摘要和来源关系。
- **CLAI-006** 每次外发生成 Receipt，支持按时间、模型、任务和数据类型查询。
- **CLAI-007** 云端不可用时提供本地降级、稍后执行或取消，不能无提示切换模型。

### 7.8 行动与审批

- **ACT-001** 行动风险分为低、中、高、禁止四级。
- **ACT-002** 中高风险行动展示目标、步骤、读取范围、写入范围和可撤销性。
- **ACT-003** 审批可以是单次、当前批次或有时效的规则授权。
- **ACT-004** 发送、发布、删除、购买、共享和权限变更默认高风险。
- **ACT-005** 执行前再次校验连接权限和数据版本，防止批准后上下文漂移。
- **ACT-006** 每步结果写入 Receipt；部分失败必须明确展示并可重试安全步骤。
- **ACT-007** 可撤销行动提供撤销入口和截止时间；不可撤销行动明确提示。

### 7.9 长期记忆

- **MEM-001** 记忆区分用户明确输入与模型推断。
- **MEM-002** 模型推断默认进入待确认状态。
- **MEM-003** 每条记忆显示来源、置信度、敏感级别、有效期和使用记录。
- **MEM-004** 用户可确认、修改、合并、冻结、过期和删除记忆。
- **MEM-005** 删除记忆后从检索和后续提示构建中立即排除。
- **MEM-006** 记忆不得包含凭据或原始秘密字段。
- **MEM-007** 重大行为建议不能仅依据低置信度记忆自动执行。

### 7.10 工作台与个性化

- **UX-001** “今天”是默认首屏，核心状态无需打开聊天即可查看。
- **UX-002** 卡片支持拖拽、尺寸、固定、隐藏和恢复默认布局。
- **UX-003** 布局和偏好保存在本地，可随 Home 导出。
- **UX-004** 每张数据卡显示来源和最近同步时间。
- **UX-005** 顶部指令栏支持搜索、导航、创建、提问和行动意图。
- **UX-006** 破坏性操作不能仅依赖颜色表达，需图标、文本和确认。
- **UX-007** 支持键盘导航、可见焦点、缩放和 reduced motion。

### 7.11 审计与隐私

- **PRIV-001** 审计覆盖本地数据访问、凭据使用、同步、模型外发和外部写操作。
- **PRIV-002** 审计记录不保存凭据和不必要的正文。
- **PRIV-003** 用户可从原始记录、记忆、Action 或连接反向查看相关审计。
- **PRIV-004** append-only 日志按链式哈希或等价机制检测篡改。
- **PRIV-005** 隐私中心展示本地数据量、云端外发、连接权限和敏感数据分布。
- **PRIV-006** 用户可执行按来源删除、全部删除和可验证导出。

## 8. 本地与云端路由策略

| 任务 | 默认执行 | 云端升级条件 | 默认审批 |
|---|---|---|---|
| 分类、标签、去重 | 本地 | 无 | 不需要 |
| 任务/实体抽取 | 本地 | 本地结果置信度低且用户请求 | 逐次 |
| 私人资料问答 | 本地 | 用户主动选择 | 逐次 + 最小披露 |
| 邮件/文档摘要 | 本地 | 超长或质量要求高 | 逐次 |
| 周计划、方案比较 | 本地预处理 + 云端可选 | 多约束复杂规划 | 逐次或任务级授权 |
| 发送邮件/改日程 | 本地规划，连接器执行 | 不依赖云端 | 高风险逐次确认 |
| 凭据相关操作 | Rust 核心 | 禁止云端 | 永不交给模型 |

## 9. 连接器优先级

### 9.1 P0

1. 本地文件：形成 Home 的原生能力。
2. 邮件：IMAP 读取；SMTP/Provider API 写回后置并需高风险审批。
3. 日历：优先标准协议或主流 Provider API，只读先行。

### 9.2 P1

任务、笔记、联系人、云盘。选择顺序依据：用户价值、授权稳定性、开放 API、增量同步能力和数据可导出性。

### 9.3 连接器验收

每个连接器必须具备权限说明、固定目的地、凭据引用、增量游标、幂等性、限速、错误分类、删除行为、数据映射和自动化测试夹具。

## 10. 非功能需求

### 10.1 安全

- Rust 是凭据、数据、网络、模型外发与外部行动的唯一授权边界。
- 默认拒绝未声明 capability。
- 连接器和模型 Worker 使用独立进程与最小权限。
- 日志、错误和遥测经过秘密扫描与字段裁剪。
- Home 数据损坏不能导致凭据泄露。

### 10.2 性能

- 工作台冷启动优先展示本地缓存，不等待连接器完成。
- 10 万条文本记录下，结构化/FTS 搜索首屏 P95 小于 2 秒（目标硬件待定义）。
- 同步、索引和本地推理不得长期阻塞 UI 主线程。
- 大对象使用流式接口，不再依赖 base64 整体传输。

### 10.3 可靠性

- 同步和 Action 使用持久队列与幂等键。
- 数据库 migration 可回滚或从备份恢复。
- 派生索引可丢弃重建。
- 应用崩溃后能够恢复未完成任务状态，并要求重新确认过期审批。

### 10.4 可移植性

- 核心记录支持 JSONL/Markdown/ICS 等开放格式导出。
- 连接器、模型与索引实现可替换。
- Home 使用显式 schema version 和 migration 清单。

## 11. 安全与隐私验收场景

1. 模型尝试读取凭据文件：不存在可读文件，Credential Broker 拒绝模型主体。
2. 连接器尝试访问未声明域名：Rust 网络 capability 拒绝并审计。
3. 云端请求包含 restricted 字段：网关阻止并要求显式覆盖。
4. 用户批准邮件草稿后源内容变化：执行前版本校验失败，要求重新确认。
5. 用户撤销连接：后续凭据解析失败，已同步本地数据按用户选择保留或删除。
6. 用户删除记忆：后续检索和提示构建均不再引用该记忆。
7. 断网期间创建外部行动：进入队列但不自动执行高风险操作，联网后再次确认。

## 12. 指标

所有产品指标默认仅保存在本地；如未来提供遥测，必须单独 opt-in 且不包含个人内容。

### 12.1 北极星指标

**每周被 DepDek 可靠闭环的个人承诺数**：从来源发现或用户创建，经确认、执行/完成，并保留可追溯记录的 Task/Action 数。

### 12.2 领先指标

- 首次连接成功率与首次同步完成时间。
- 每周跨来源搜索成功会话数。
- 抽取任务的确认率、修改率和忽略率。
- 本地完成率与云端升级率。
- 云端外发预览的取消率和策略覆盖率。
- Action 成功率、部分失败率和撤销率。
- 记忆候选确认/修改/删除比例。
- 同步健康率与冲突解决时长。

### 12.3 护栏指标

- 凭据泄漏事件：必须为 0。
- 未审批外部高风险写操作：必须为 0。
- 无回执云端模型请求：必须为 0。
- 来源不可追溯的 Derived Record 占比：必须为 0。

## 13. MVP 验收旅程

### Journey A：首次使用

用户创建 Home，连接一个邮箱，选择最近 30 天，同步成功；“今天”显示待处理邮件与抽取任务，原始邮件来源可打开，凭据仅存在钥匙串。

### Journey B：本地问答

用户搜索“我和某人的下次会议及未完成承诺”，系统跨邮件与日历返回事实、来源和候选任务，全程不产生云端 Receipt。

### Journey C：云端规划

用户要求制定下周项目计划。系统先本地聚合约束，展示外发预览；用户批准后调用指定云端模型，返回计划并落为本地 Task 草稿，隐私中心可查看完整回执。

### Journey D：外部行动

用户让 DepDek 修改日程。Action Sheet 展示变化和冲突，用户确认后写回服务；结果、远端 ID、时间和撤销能力进入 Receipt。

### Journey E：记忆治理

系统从多次行为中生成“上午适合深度工作”的候选记忆。用户查看来源并修改适用时间，确认后后续排程建议引用该记忆；删除后不再使用。

## 14. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 连接器维护成本高 | 同步不稳定 | 首发少而深；SDK、契约测试、健康诊断 |
| 统一模型过度抽象 | 丢失来源语义 | Canonical + 原始快照双层；可扩展字段 |
| 本地模型质量波动 | 用户不信任 | 置信度、待确认、来源、可替换模型 |
| “本地优先”被云端功能稀释 | 品牌承诺受损 | Model Gateway 强制路径和可验证回执 |
| 自动化误操作 | 现实损失 | 风险分级、预览、版本校验、撤销和限速 |
| 数据规模拖慢桌面端 | 体验下降 | SQLite/FTS、后台队列、增量索引、对象流式接口 |
| 用户误解记忆为事实 | 个性化偏差 | 候选状态、来源、有效期、使用记录和纠错 |

## 15. 发布门槛

MVP 进入公开测试前必须满足：

- 威胁建模和关键边界安全评审完成。
- 凭据迁移出普通 settings/vault 文件。
- 三个 P0 连接器通过契约和故障注入测试。
- 云端请求无法绕过 Model Gateway。
- 所有外部写操作进入 Action/Approval/Receipt。
- Home 备份、迁移和恢复演练通过。
- WCAG 关键路径键盘与可读性检查通过。
- 崩溃恢复和离线队列验证通过。
