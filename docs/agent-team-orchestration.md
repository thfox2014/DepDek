# Agent 团队协作（第一步）

这是把 Agent Team 从「各自独立的会话」推进到「可以互相委托」的编排层。它不是模型网关，也不引入 shell 或新的文件权限。

## 运行在哪

协作队列放在 sidecar，因为会话和工具都在这里。Rust 只做两件事：把 `team/event` 原样转成 `team://event`，以及通过 `team/audit` 把生命周期写入现有的 append-only 审计日志（`op: "team"`，路径是逻辑主体，不是磁盘文件）。

```
发起方 Pi 会话
  delegate_task / send_agent_message
        │ 立即返回
        ▼
  TeamOrchestrator 队列（queued）
        │ 目标会话空闲
        ▼
  目标会话 runTurn（只用该会话已有工具）
        │ done / failed / cancelled
        ▼
  结果回合送回发起方（该回合禁止再次委托）
```

## 工具

| 工具 | 行为 |
|---|---|
| `list_teammates` | 列出其他在线会话的显示名、id、引擎和是否正忙 |
| `delegate_task` | 把一件工作交给命名队友，发起方继续和用户对话 |
| `send_agent_message` | 给队友送一条消息，同样异步，回复之后送回 |

这三个工具挂在每个 Pi 会话上，不受 `enabled_skills` 过滤。空技能列表仍然不能读写文件；它只能把工作交给**已经具备相应技能**的队友。Harness 会话不能发起协作，但可以接收一段文本任务。`agent/analyze` 保持只读，不注册这些工具。

名称按 session id 精确匹配，否则按显示名大小写不敏感匹配。重名必须改用 id。没启动的 Agent 不会被自动拉起。

## 循环与限额

- 深度最多 3。用户回合深度为 0，第一次委托是 1。
- `chain` 记录经过的 session。目标已在链上，或目标就是自己，直接拒绝。
- 结果回传回合的来源标记为 `result`，协作工具在这一回合一律拒绝，避免「做完 → 再委托 → 再回传」自己转起来。
- 每个发起方同时最多 4 个未完成任务，全局最多 16 个。完全相同的发起方、目标和正文不重复入队。
- 委托正文 4000 字符，消息 2000 字符。仪表盘上的结果预览截到 500 字符。

拒绝也会记一条 `status: rejected` 的审计，但不会出现在任务列表里。

## 取消

面板只对 `queued` 和 `running` 提供取消。排队任务直接标为 `cancelled`。正在执行的任务只中止这次协作回合：编排器记住这个 task id，再调用会话的 abort，不会把用户自己正在进行的另一段对话误停掉。会话关闭时，指向它或由它发起、仍在排队的任务一并取消。

## 前端

`AgentTeamDashboard` 列出进行中和最近完成的协作，状态来自 `team://event`，打开页面时用 `team_list` 补一次快照。浏览器 UX 预览没有 sidecar，面板使用两条本地样例，取消只改本地状态。

## 还没做

- 任务不跨 sidecar 重启保留；审计日志里留着轨迹。
- 不能按技能策略限制「谁可以委托给谁」。现在的规则是：被委托者用自己的技能。
- 结果回传会再消耗发起方一轮模型调用。
- Harness 不能主动发起委托。
- 没有跨机器、跨进程的团队总线。这一步只让同一 sidecar 里的会话协作。
