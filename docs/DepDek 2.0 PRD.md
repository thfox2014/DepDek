# DepDek 2.0 PRD：本地个人数据操作系统

> 状态：产品需求基线草案
> 日期：2026-08-09
> 依据：`DepDek 2.0 Concept.md`
> 目标版本范围：V0.3—V0.6

## 1. 背景

当前 DepDek 已具备桌面工作台、文件浏览、邮箱、日历、待办、统一任务框、Agent Team、Copilot、Vault/RPC 和本地优先的技术基础。

但当前产品仍以页面导航、卡片和文件目录为主要组织方式；Agent 只在用户打开 Copilot 或 Agent Team 后出现。数据也尚未形成跨来源的统一对象，连接页面更接近账号配置，而不是个人数据取回与授权控制中心。

DepDek 2.0 需要完成三个转变：

1. 从“功能页面集合”转为“个人数据对象系统”；
2. 从“用户主动 Chat”转为“Agent 事件驱动工作 + 用户审批”；
3. 从“账号连接”转为“分级数据取回 + 本地权限控制”。

## 2. 产品目标

### 2.1 P0 目标

1. 用户能够在本地持有文件、邮件、日历、订单和行程的原始数据与归一对象。
2. Agent 能够在数据进入后自动分类、提取和关联，并以结构化 Proposal 呈现。
3. 用户能在统一“需要我决定”页面确认、修改或拒绝 Agent 提案。
4. 所有执行中的同步、导入、解析、推理和外部行动进入统一持久任务框架。
5. 用户能够明确看见每个连接的数据范围、连接方式、权限、同步状态、错误和撤销方式。
6. 凭据、个人原文和敏感信息不因 Agent 或云端模型调用而失控。

### 2.2 P1 目标

1. 支持官方数据下载包和票据导入，覆盖抖音、美团、携程等典型个人数据来源。
2. 支持 Agent 订阅领域事件，并按风险策略自动执行低风险本地操作。
3. 支持跨邮件、日历、文件和订单的本地查询与规划。
4. 支持受控云端模型升级与数据外发回执。

### 2.3 非目标

- 不承诺获取平台未向用户或开发者开放的数据。
- 不通过破解、注入、私有数据库读取或凭据重放实现连接。
- 不在本阶段自动购买、支付、退款或提交高风险表单。
- 不以 Chat 取代完整邮箱、日历、文件和订单界面。
- 不在没有来源和审批的情况下让模型修改主数据。

## 3. 目标用户与 JTBD

### 3.1 目标用户

同时使用多个数字服务、长期积累大量文件和消息、重视隐私与可迁移性的个人专业用户，包括独立开发者、创作者、研究者、自由职业者和小团队负责人。

### 3.2 核心任务

- 当我的资料散落在不同服务时，我想把属于自己的数据带回本地并长期保留。
- 当邮件、日历、订单和文件产生下一步时，我想让 Agent 自动发现，但由我决定是否执行。
- 当我询问复杂问题时，我想得到跨来源、有依据的答案，而不是只搜索文件名。
- 当平台或模型更换时，我想保留数据、关系、记忆和处理规则。
- 当需要使用云端能力时，我想知道具体发送了哪些数据以及为什么。

## 5. 核心体验需求

### 5.1 需要我决定

- **DEC-001** 系统按 Proposal、Approval、Conflict、MemoryCandidate 四类展示待决定事项。
- **DEC-002** 每个项目显示依据、来源、Agent、置信度、建议变化和风险等级。
- **DEC-003** 用户可批准、修改后批准、拒绝、稍后处理和批量处理。
- **DEC-004** 批量批准只能作用于相同操作类型、相同连接和相同风险等级。
- **DEC-005** 高风险远端写操作不支持静默批量批准。
- **DEC-006** 决定后生成 Approval 和后续 Action；拒绝原因可用于本地规则优化。

### 5.2 正在执行

- **OPS-001** 所有同步、导入、解析、索引、推理、批处理和外部行动统一进入 Job 列表。
- **OPS-002** Job 支持排队、运行、等待输入、暂停、重试、成功、部分成功、失败和取消状态。
- **OPS-003** 页面显示总进度、当前步骤、处理对象、速率、预计剩余时间和最近日志。
- **OPS-004** 完整日志写入本地持久存储，重启后可查看。
- **OPS-005** Job 可以最小化到后台，不阻塞用户继续使用相关页面。
- **OPS-006** Job 结果关联到输入对象、输出对象和 Receipt。

### 5.3 Today

- **TODAY-001** 首屏优先展示需要决定、正在执行、今日时间线和今日承诺。
- **TODAY-002** 每个摘要卡显示真实来源和最近更新时间。
- **TODAY-003** Agent 建议必须说明依据，不以普通通知形式混入事实。
- **TODAY-004** 连接和系统健康降级为紧凑状态区，只有异常时提升优先级。

### 5.4 结构化领域页面

- **DOMAIN-001** 邮箱、日历、订单和文件采用各自成熟的领域交互，而不是 Chat 列表。
- **DOMAIN-002** 每个对象显示 Agent 处理状态、来源、敏感级别和最近同步时间。
- **DOMAIN-003** 领域页面提供统一对象动作：加入待办、关联项目、关联人物、加入行程、请求 Agent 处理。
- **DOMAIN-004** Agent 生成的字段在确认前以候选状态显示，不覆盖来源事实。
- **DOMAIN-005** 用户可从任何派生对象打开原始来源和生成链路。

### 5.5 上下文 Agent 与 Chat

- **CHAT-001** Agent 抽屉默认获得当前页面和选中对象的受控上下文。
- **CHAT-002** 用户可以切换 Agent，但只能看到具备当前数据域权限的 Agent。
- **CHAT-003** 跨对象查询返回事实、来源和推断分区。
- **CHAT-004** 任何准备修改状态或调用外部服务的回答必须生成 Proposal/Action Sheet。
- **CHAT-005** 对话关闭后 Proposal、Action、Task 和查询结果仍可从结构化页面访问。
- **CHAT-006** Chat 不得显示或索取凭据明文。

## 6. 个人对象与数据需求

### 6.1 通用对象字段

```ts
type PersonalObject = {
  id: string;
  type: string;
  title?: string;
  createdAt?: string;
  updatedAt?: string;
  sourceRefs: SourceRef[];
  provenance: Provenance[];
  sensitivity: "public" | "personal" | "sensitive" | "restricted";
  localState: "clean" | "dirty" | "conflict" | "deleted";
  schemaVersion: number;
};
```

### 6.2 新增关键对象

- **OBJ-001 Order**：平台、商户、商品/服务、金额、状态、下单时间、履约时间、退款、票据和来源。
- **OBJ-002 Trip**：出发/到达、时间、参与者、交通、住宿、订单、日历事件和相关文件。
- **OBJ-003 Transaction**：金额、币种、对方、支付方式、时间、关联订单和票据。
- **OBJ-004 Proposal**：类型、依据、建议变化、置信度、风险、责任 Agent 和状态。
- **OBJ-005 Job**：输入、步骤、进度、日志、输出、重试、幂等键和状态。
- **OBJ-006 Receipt**：主体、能力、数据范围、外发/执行目标、时间、结果和错误。

### 6.3 来源与去重

- **DATA-001** 导入和同步先保存原始快照，再进行解析和归一。
- **DATA-002** 同一对象可拥有多个来源，例如邮件确认、平台数据包和 PDF 发票共同指向一个 Order。
- **DATA-003** 自动合并必须达到策略阈值；低置信度时生成合并 Proposal。
- **DATA-004** 删除归一对象不自动删除原始来源或远端记录。
- **DATA-005** 所有索引均可从原始数据和归一主记录重建。

## 7. Agent 与事件机制

### 7.1 事件总线

- **EVT-001** 领域对象创建、更新、删除、冲突和同步失败均产生统一事件。
- **EVT-002** 事件包含 `event_id`、类型、对象引用、来源、版本、时间、敏感级别和 trace ID。
- **EVT-003** Agent 只能订阅已被策略授权的数据域和事件类型。
- **EVT-004** 事件处理至少一次投递，处理器使用幂等键防止重复结果。
- **EVT-005** 失败事件进入可重试队列，并显示于正在执行页面。

### 7.2 Agent Profile

- **AGENT-001** Agent 配置角色、订阅、数据范围、工具、模型、预算和自动放行策略。
- **AGENT-002** 默认 Agent 仅使用本地模型和只读本地能力。
- **AGENT-003** Agent 不获得直接文件系统、shell、Secret Store 或任意网络访问。
- **AGENT-004** Agent 输出必须匹配声明的结构化 schema。
- **AGENT-005** Agent 使用云端模型时必须经过 Model Gateway。
- **AGENT-006** Agent 失败时可升级到指定 Agent、用户决定或稍后重试。

## 8. 连接中心与数据取回

### 8.1 Connection Profile

- **CONN-001** 每个连接声明服务、账号身份、连接方式等级、数据类型、时间范围和同步方向。
- **CONN-002** 页面显示凭据保存方式，但不显示凭据明文。
- **CONN-003** 页面显示最近同步、数据量、游标、错误、下次计划和原始数据路径。
- **CONN-004** 用户可暂停、重新授权、重导、撤权和删除连接。
- **CONN-005** 删除连接时分别选择保留本地数据、删除归一对象或删除所有本地副本。
- **CONN-006** 连接方式变化时保留历史来源和 Receipt。

### 8.2 Personal Data Import Wizard

- **IMPORT-001** 用户选择平台后看到官方数据获取方式和能力说明。
- **IMPORT-002** 向导区分 API 连接、数据包、票据和手动上传。
- **IMPORT-003** 导入前进行文件类型、病毒、压缩炸弹、路径逃逸和大小检查。
- **IMPORT-004** 导入预览显示识别的数据类型、数量、时间范围和敏感数据。
- **IMPORT-005** 用户确认后才写入归一对象；取消不删除原始用户文件。
- **IMPORT-006** 同一数据包重复导入不产生重复对象。
- **IMPORT-007** 解析器版本和映射结果写入 provenance，支持重新解析。

### 8.3 平台覆盖策略

| 平台 | 首选方式 | 补充方式 | 首期能力 |
|---|---|---|---|
| 邮箱 | IMAP / Provider OAuth | MBOX/EML | 增量读取、附件、行动项 |
| 日历 | CalDAV / Provider OAuth | ICS | 聚合、冲突、只读优先 |
| 抖音 | 官方个人信息下载包 | 获批 OAuth scope | 作品、互动、交易等按包能力映射 |
| 美团 | 官方个人信息下载包 | 订单票据/通知 | 订单、商户、履约、金额 |
| 携程 | 邮件、行程单、票据 | 官方复制请求/合作接口 | Order + Trip + Event |
| 微信 | 官方备份/用户导出 | 账单、收藏文件 | 可合法解析的数据，不接管账号 |

## 9. 凭据、网络与权限

- **SEC-001** 凭据保存到 OS Keychain/Secret Store，Home 只保存不透明 CredentialRef。
- **SEC-002** Connector 通过 Credential Broker 使用凭据，不能读取可展示明文。
- **SEC-003** 每个 Connector 声明固定网络目的地、协议和 capability。
- **SEC-004** Rust Core 默认拒绝未声明网络、文件和数据域访问。
- **SEC-005** 日志、错误、审计和提示词进行秘密扫描和字段裁剪。
- **SEC-006** 用户撤销连接后，后续 CredentialRef 解析立即失败。
- **SEC-007** 远端写操作执行前再次校验授权、对象版本和审批有效期。
- **SEC-008** 敏感操作支持应用解锁或系统生物识别确认。

## 10. 本地与云端模型

### 10.1 默认本地处理

- 分类、标签、去重；
- 订单、人物、日期、任务和实体抽取；
- 文档与邮件摘要；
- 全文/语义检索；
- 敏感字段识别和脱敏；
- Proposal 生成；
- 个人问答和上下文组装。

### 10.2 云端升级

- **CLOUD-001** 复杂规划或质量不足时，系统可提出云端升级建议。
- **CLOUD-002** 外发前展示原因、模型、字段、敏感级别和预计成本。
- **CLOUD-003** Restricted 数据默认禁止外发。
- **CLOUD-004** 用户可选择仅本地、逐次询问、特定任务自动三档策略。
- **CLOUD-005** 每次调用生成 Receipt，关联输入对象和输出对象。
- **CLOUD-006** 云端不可用时提供本地降级、排队或取消，不能静默更换模型。

## 11. 风险分级与审批

| 等级 | 示例 | 默认策略 |
|---|---|---|
| L0 | 本地索引、分类、标签 | 自动允许并记录 |
| L1 | 生成 Proposal、关联对象 | 自动允许，变化可回退 |
| L2 | 修改本地主记录、批量归档 | 策略允许或逐次确认 |
| L3 | 云端外发、远端创建/修改 | 显式预览和批准 |
| L4 | 远端删除、发送、提交表单 | 逐次确认，执行前复核 |
| L5 | 付款、交易、高影响决定 | 首期禁止自动执行 |

## 12. 关键用户旅程

### Journey A：导入美团个人数据

选择美团 → 查看官方个人信息下载路径 → 用户获取 ZIP → 拖入 DepDek → 本地安全扫描 → 预览订单和商户 → 确认导入 → 创建 Order/Organization/Transaction → Agent 提出待办和记忆候选 → 用户确认。

### Journey B：从邮件形成出差行程

手动收取邮箱 → 保存原始邮件 → 本地模型识别机票、酒店和会议 → 合并为 Trip Proposal → 用户确认 → 创建 Trip/Event/Task → 如需写回日历，生成 L3 Action → 用户批准 → 保存回执。

### Journey C：跨来源查询

用户询问“上半年去上海出差花了多少钱” → 本地检索 Trip、Order、Transaction、邮件和票据 → 返回汇总、缺失项和来源 → 用户要求生成报销清单 → 形成本地 Document Proposal → 确认后保存文件。

### Journey D：复杂周计划

本地模型收集日历、任务、邮件承诺和行程 → 判断需要云端复杂规划 → 展示最小化外发包 → 用户批准 → 云端返回策略 → 本地 Agent 结合完整私人上下文生成 Task/Event Proposal → 用户最终确认写回。

## 13. 非功能需求

### 13.1 性能

- 10 万条文本对象下，本地搜索首屏 P95 小于 2 秒。
- 领域页面先显示本地缓存，不等待同步和模型完成。
- 大型数据包、附件和视频采用流式处理。
- 邮件和文件长列表使用虚拟滚动，不一次加载全部正文。

### 13.2 可靠性

- Job、Action 和同步游标持久化。
- 应用崩溃后恢复任务状态，过期高风险审批重新确认。
- 数据包和增量同步均使用幂等键。
- 解析器、索引和派生记录可丢弃重建。
- migration 可回滚或从备份恢复。

### 13.3 可移植性

- 原始对象和归一记录支持 JSONL、Markdown、ICS、EML 等开放格式导出。
- Order/Trip/Transaction schema 带版本和 migration。
- 凭据默认不随 Home 导出。
- 用户可导出连接清单、策略和 Receipt。

### 13.4 可访问性

- 所有核心操作可键盘完成。
- 状态不只依赖颜色表达。
- Proposal 风险、Agent 结论和来源可被辅助技术读取。
- 批量操作提供清晰选中数量和不可逆提醒。

## 14. 版本计划

### V0.3：Personal Object Foundation

- Canonical Object Store；
- SourceRef / Provenance；
- Order、Trip、Transaction 基础 schema；
- Proposal 与“需要我决定”；
- Today 首页改为决策/执行导向；
- V0.2 邮件数据迁移。

退出标准：邮件或导入文件可生成可追溯对象与 Proposal，关闭 Chat 后状态完整保留。

### V0.4：Trust & Connection Center 2.0

- OS Keychain / Credential Broker；
- Connection Profile；
- 数据取回向导和通用导入框架；
- 权限、网络目的地和撤权；
- 数据包原始快照与重导。

退出标准：普通文件、日志、前端状态和模型上下文中不存在凭据明文。

### V0.5：Agent Operations

- 领域事件总线；
- 持久 Job Queue；
- Agent 订阅与结构化输出；
- Action / Approval / Receipt；
- 正在执行、活动与回执页面。

退出标准：Agent 可因数据事件自动生成提案；高风险行动未经审批无法执行。

### V0.6：Personal Data Intake Packs

- 美团个人信息包解析器；
- 抖音个人信息包解析器；
- 携程邮件/票据/行程解析器；
- 微信合法导出文件、账单和收藏文件导入；
- 跨来源订单/行程去重和合并。

退出标准：至少三个平台可通过非侵入、可重复的方式形成 Order/Trip/Transaction 对象。

## 15. 验收场景

1. 没有配置 Agent 时，用户仍可查看全部本地数据；系统明确提示未处理状态，而不是空白 Chat。
2. 新邮件进入后，本地模型自动生成行动项 Proposal，用户可在“需要我决定”中确认。
3. 用户重复导入同一个美团数据包，不产生重复订单。
4. 用户从 Order 打开原始数据包记录、邮件或票据。
5. Agent 试图访问未授权文件、凭据或域名时，被 Rust Core 拒绝并审计。
6. 云端请求包含 restricted 字段时，Model Gateway 阻止请求。
7. 用户批准日历写回后源事件发生变化，执行前版本校验失败并要求重新批准。
8. 应用在导入过程中崩溃，重启后 Job 显示中断状态，可安全重试。
9. 用户撤销连接后，Connector 无法继续使用 CredentialRef。
10. 用户删除 MemoryFact 后，后续检索和提示构建不再使用该记忆。

## 16. 指标与发布门

### 16.1 核心指标

- 每周可靠闭环个人承诺数；
- 每周新增可追溯个人对象数；
- Proposal 确认率、修改率、拒绝率；
- 本地完成率和云端升级率；
- 连接和导入任务成功率；
- 外部 Action 执行成功率；
- 从来源进入到结构化可用的时间。

### 16.2 安全红线

- 凭据泄漏事件必须为 0；
- 未授权云端外发必须为 0；
- 未批准高风险远端写操作必须为 0；
- 无来源的主数据覆盖必须为 0。

### 16.3 工程发布门

1. 产品门：范围、非目标、迁移和验收明确；
2. 设计门：数据模型、状态机、接口、权限和错误分类完成；
3. 契约门：所有跨层变化先更新 `docs/contract.md`；
4. 实现门：Rust、sidecar、React 分层实现且无绕过信任边界；
5. 测试门：单元、契约、迁移、故障注入和关键 UI 流程通过；
6. 安全门：秘密扫描、越界访问、未授权网络和外发用例通过；
7. 发布门：可构建、可安装、可回滚，旧 Home 数据可迁移。

## 17. 主要风险

| 风险 | 影响 | 缓解方案 |
|---|---|---|
| 平台数据导出格式变化 | 解析失败 | 原始包留存、版本识别、解析器夹具、可重跑 |
| 用户误以为所有连接都是实时 | 信任下降 | 明确显示 API/数据包/票据等级和新鲜度 |
| Agent 建议过多 | 决策疲劳 | 置信度阈值、聚合提案、个性化抑制规则 |
| 归一模型过早复杂化 | 开发失控 | 先覆盖 Message/Event/Task/Order/Trip/Document |
| 本地模型质量不稳定 | 错误关联 | 候选状态、来源、置信度、可逆合并 |
| 云端能力稀释本地承诺 | 品牌受损 | Model Gateway、外发预览、Receipt、默认本地 |
| 新连接器扩大安全面 | 凭据或网络风险 | Credential Broker、目的地白名单、最小 capability |
