# DepDek 个体数据 AI 分析与建议机制设计

> 版本：V0.3 设计稿 · 2026-08-11
>
> 核心承诺：AI 可以理解本地数据、解释依据、提出建议；未经用户确认，不修改、不移动、不删除、不发送、不写回任何数据。

## 1. 产品目标

DepDek 的 AI 不是一个会替用户“自动收拾”的黑盒，而是个人数据上的只读分析层：

1. 把文件、邮件、日历和后续连接器数据统一成有来源的本地上下文。
2. 由本地模型或本地规则识别事实、关系、风险和可能的下一步。
3. 将结果呈现为可追溯的建议，用户可以忽略、修改或在未来版本中单独确认执行。
4. 分析过程不携带凭据，不调用发送、删除、移动、同步和外部写回工具。

## 2. 总体架构

```text
本地数据源
  ├─ 文件 / 图片 / 视频 / 文档
  ├─ 邮件本地副本
  └─ 日历本地事件
        │
        ▼
统一上下文快照 Context Snapshot
  ├─ sourceRef：原始路径 / 邮件 ID / 日历事件 ID
  ├─ content：最小必要文本或元数据
  ├─ sensitivity：敏感级别
  └─ capturedAt：快照时间
        │
        ▼
只读分析通道 agent/analyze
  ├─ 仅允许 read_file / list_files / search_files
  ├─ 默认只选本地 Provider
  ├─ 结构化 JSON 输出
  └─ 不创建持久 Chat，不注册写入工具
        │
        ▼
AnalysisResult
  ├─ facts：来源明确陈述
  ├─ inferences：模型推断
  └─ suggestions：等待用户确认的建议
        │
        ▼
模块内建议面板 / Today 聚合 / 历史审计
```

分析层与执行层严格分离。后续如要执行，必须由独立 Action Engine 创建新的审批流程，不能复用 `agent/analyze`。

## 3. 统一领域模型

### 3.1 AnalysisContext

```ts
type AnalysisContext = {
  domain: "mail" | "files" | "calendar";
  title: string;
  sources: Array<{
    label: string;
    path?: string;
    content: string;
  }>;
};
```

上下文遵循“最小必要原则”：

- 邮件默认使用当前邮件或当前列表最多 12 封的摘要、主题、发件人、日期和正文片段。
- 文件使用当前选中文件的路径、类型、大小；文本文件再提供正文，图片/视频暂时只提供元数据。
- 日历使用当前选中日期或当前月份最多 40 个事件的标题、时间、地点、来源和描述。
- 账号密码、SMTP/IMAP 配置、访问令牌永远不进入上下文。

### 3.2 AnalysisResult

```ts
type AnalysisResult = {
  facts: string[];
  inferences: string[];
  suggestions: Array<{
    title: string;
    reason: string;
    confidence?: number;
    risk?: "low" | "medium" | "high";
  }>;
  sourceCount: number;
  model: string;
  mode: "local-model" | "local-rules" | "preview";
  notice?: string;
};
```

显示规则：

- 事实使用中性颜色，可点回来源。
- 推断使用黄色提示，必须明确“推断”字样。
- 建议使用紫色卡片，显示置信度和风险，仅有“查看来源/忽略”语义，不出现“立即执行”按钮。
- 每个面板固定显示“只给建议，不自动处理”。

## 4. 三个模块的 AI 体验

### 4.1 邮件

入口：收件箱的“AI 整理”、阅读器顶部的“AI 分析”，以及邮件列表右键菜单中的“AI 分析这封邮件”。

分析内容：

- 回复状态：是否出现明确问题、请求或待回复信号。
- 时间/付款风险：截止日期、续费、付款、合同节点。
- 行动候选：可考虑加入待办的承诺或下一步。
- 主题聚类：当前邮件是否与已有项目/文件/日历事件相关。

建议示例：

- “核对域名续费日期，必要时手动加入待办。”
- “邮件中包含一个待回复问题，建议先打开原文确认上下文。”

禁止行为：标记已读、归档、移动文件夹、生成并发送回复、远程删除。

### 4.2 文件

入口：文件预览右上角“AI 分析”。

分析内容：

- 文档主题、摘要、关键日期和人物。
- 文件命名与所在文件夹是否可能不一致。
- 可能重复、过期或需要人工复核的文件。
- 分享前的敏感信息提醒。

图片/视频在当前版本只分析元数据，不声称已经完成 OCR、视觉识别或视频理解；后续接入本地多模态模型时必须在结果中注明模型和识别范围。

禁止行为：重命名、移动、删除、覆盖、上传或自动建立知识链接。

### 4.3 日历

入口：日历工具栏“AI 分析”。

分析内容：

- 当前日期或月份的时间冲突与过密安排。
- 会议准备、通勤和缓冲时间建议。
- 事件标题、地点和来源之间的异常或缺失信息。
- 与邮件/待办的潜在关联（仅在上下文实际提供关联来源时推断）。

建议示例：

- “两个事件间只有 10 分钟，建议人工确认是否需要缓冲。”
- “该会议缺少地点信息，建议打开原始邀请确认。”

禁止行为：自动改时间、取消事件、创建事件、同步外部日历或加入待办。

## 5. 本地模型与隐私路由

### 5.1 Provider 策略

- `agent/analyze` 只接受本地 OpenAI-compatible Provider：`localhost`、`127.0.0.1` 或 `::1`。
- 未配置本地模型时，前端降级为本地规则建议，并明确说明没有调用云端模型。
- 云端 Provider 不能被分析层隐式使用；若未来开放云端分析，必须新增显式开关、数据预览、范围确认和外发审计。

### 5.2 使用现有 Agent 配置

- 分析面板从当前 Home 的 `settings.agents` 读取已保存的 Agent Team 配置。
- 选择器只显示绑定本地 Provider 的 Agent，分析请求复用该 Agent 的名称、模型和系统提示词，但不复用持久聊天上下文。
- 这样用户可以在 Agent Team 中维护“邮件整理顾问”“文件研究顾问”“日历规划顾问”等角色，再在各领域面板选择使用哪个 Agent。
- 没有本地 Agent 时，面板使用本地规则建议，并明确提示；不会偷偷选用云端 Agent。

#### Tanvis 单封邮件分析 Agent

- Agent Team 内置 Tanvis 配置区，默认 Agent id 为 `tanvis`，绑定本地 OpenAI-compatible Provider。
- 配置保存在当前 Home 的 `agents/tanvis/agent.md`、`skill.md`、`mcp.md`；`settings.json` 只保存 Agent 与 Provider 的引用目录。
- 单封邮件入口优先选择 Tanvis，并将三份 Markdown 作为本地提示资料合并到一次性 `agent/analyze` 请求中。
- `mcp.md` 在 V0.3 只作为说明文本，绝不注册工具、执行命令或访问外部服务；所有分析仍是只读。

### 5.3 凭据边界

- API key、邮箱密码、日历密码只传给连接所需的底层服务，不进入分析 prompt。
- 分析会话是一次性的，不出现在 Agent Team 的持久会话列表中。
- 分析会话只注册只读 Vault 工具，工具集合由 sidecar 强制裁剪。
- 任何建议都保存来源引用和分析时间；当前版本先在界面展示，后续写入 `analysis/history.json`。

## 6. 统一接口

### `agent/analyze`

请求：

```json
{
  "provider": {
    "kind": "openai-compatible",
    "model": "qwen3:8b",
    "base_url": "http://127.0.0.1:11434/v1"
  },
  "text": "请分析……",
  "system_prompt": "只读分析，不要修改任何数据。"
}
```

响应：

```json
{
  "text": "{\"facts\":[...],\"inferences\":[...],\"suggestions\":[...]}"
}
```

sidecar 运行完成后销毁临时 Agent，不发送 `agent/event` 到持久 Chat。Rust 仍然是唯一 Vault 信任边界。

## 7. 任务与失败策略

V0.3 的单条分析是前台短任务；超过 1 秒应显示“本地分析中”。后续批量分析使用统一任务框架：

```text
待分析 → 快照完成 → 分析中 → 建议待查看 → 已查看 / 已忽略 / 失败
```

- 分析失败不影响邮件、文件和日历正常浏览。
- 模型返回非 JSON 时降级为规则建议，并标记失败原因。
- 上下文过长时先截断并显示“已使用摘要片段”。
- 同一个来源在 5 分钟内可复用结果，来源发生变化则失效。

## 8. 版本路线

| 版本 | 内容 | 执行边界 |
|---|---|---|
| V0.3 | 只读分析通道、邮件/文件/日历入口、事实/推断/建议分层 | 零自动处理 |
| V0.4 | 分析历史、来源回溯、建议去重、Today 聚合 | 仍需逐条确认 |
| V0.5 | Proposal 对象、用户修改建议、批量确认预览 | 确认后才进入 Action Engine |
| V0.6 | 低风险本地动作审批、撤销和审计 | 外部写回逐次确认 |
| V0.7 | 记忆候选、个性化抑制和策略中心 | 用户治理优先 |

## 9. 验收标准

1. 邮件、文件、日历都有可见的“AI 分析”入口。
2. 本地模型存在时，分析由 `agent/analyze` 完成；不存在时明确降级，不调用云端。
3. 分析会话不能调用写入、删除、收取邮件或日历写回工具。
4. 结果始终分为事实、推断、建议，并显示来源数量和模型/规则模式。
5. 点击分析前后，原始邮件、文件、日历事件内容和状态不发生变化。
6. 前端、sidecar、Rust 测试覆盖分析接口和只读工具边界。
